# Data quality notes — KKBox

Generated by `scripts/01_data_quality.py`. Every number below is recomputed on each run.

## Coverage

- Transactions: 22,975,416 rows (v1 + v2, exact duplicates removed), 2,426,143 users, 2015-01-01 → 2017-03-31.
- Members: 6,769,473 rows.
- Churn labels: train_v1 992,931 users (6.4% churn, Feb 2017 expiries); train_v2 970,960 users (9.0% churn, Mar 2017 expiries).
- User logs: 410,502,905 rows. `total_secs < 0`: 61,493; `total_secs` > 24h in one day: 147,193. Both are overflow artefacts in the source — `total_secs` is clipped to [0, 86400].
- **Left-censoring:** no transactions before Jan 2015, so members on long plans bought earlier are invisible until they renew. Metrics are reported from **Jul 2015** onward (6-month warm-up).

Most common plan lengths (non-cancel transactions): 30 days (84.1%), 0 days (3.7%), 31 days (3.2%), 7 days (2.6%), 410 days (0.7%), 195 days (0.6%).

## Churn definition

Kaggle's label: a user is churned if there is **no new valid subscription within 30 days after the current membership expires**. The monthly snapshot (Step 2) uses the same rule, so the metric churn rate and the model labels agree.
